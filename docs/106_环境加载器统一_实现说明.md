## 接缝

- **接缝**：层接缝（shell 脚本 ↔ 进程环境变量）。本次**修改**已有接缝，**新增**一个共享实现点。
- **状态所有权**：进程环境变量由 `scripts/lib/load-env.sh` 的 `load_env_file` **独占写入**。此前 `scripts/dev-up.sh` 与 `scripts/dev-local-start.sh` 各持一份写入逻辑。
- **不变量**（三条，都必须永远成立）：
  1. **优先级唯一**：真实环境变量 > 后加载的文件 > 先加载的文件。
  2. **两份 shell 实现不存在**——同一份语义只有一个实现点，所以「它们是否一致」这个问题不该被提出。
  3. **一行坏输入不能中断整份文件**：畸形行报告并跳过，后续正常行照读。
- **证明**：`scripts/check-env-loaders.sh`（17 条断言）。它已接进 `scripts/dev-check.sh`，所以**每次门禁都跑**。

---

## 根因

不是「某个值配错了」。是**同一份语义有多份实现，且其中一份结构上无法被满足**。

### 一、`.env.dev` 是一个不可能存在的文件

```
$ ls .env.dev                     → 不存在
$ git ls-files | grep -i env      → 只有 configs/*.env.example
$ grep -n env .gitignore          → 6:.env   7:.env.*
```

`.gitignore` 的 `.env.*` 让它**永远无法被提交**。而 `scripts/dev-local-start.sh` 在它缺失时 `exit 1`。

### 二、那个硬失败是**承重的**

读 `dev-local-start.sh` 的配置阶段会发现它**全文不设置 `MYSQL_DSN`**（`:179-182` 只导出 `HTTP_ADDR` / `VOICE_GATEWAY_HTTP_ADDR` / `VOICE_GATEWAY_WSS_URL` / `APP_SERVER_INTERNAL_URL`）。

所以 `.env.dev` 缺失时若不退出，结果不是「起不来」，而是**更坏的**：MySQL 与 Redis 健康检查全绿，而 app-server 因为拿不到 DSN **静默退回内存存储**。

**守卫的意图是对的，依赖是错的。** 因此「把 `.env.dev` 改成可选」这个显而易见的修法是错的——它会把一个响亮的失败换成一个静默的错误。

### 三、两份 shell 实现已经分歧，分歧被写成了规避说明

`.env.volc.local` 的文件头（`4-9` 行）自己写着：

```
# ⚠️ 值里不要带行内注释。三个加载器里 scripts/dev-local-start.sh 用
#    `IFS='=' read` 逐行取，它只剥掉整行注释，不剥行内注释 ——
#    `KEY=abc  # 说明` 会变成以 "abc  # 说明" 为值，然后鉴权失败。
#    dev-up.sh 会剥，但别依赖这件事。
```

**用文档规避代码缺陷，不是保护，是保护的样子。** 两份实现之所以能分歧下去，是因为**它们各自都无法被断言**——这正是 `AGENTS.md` §7 的 R7 要问的形状。

---

## 方案

**把两份 shell 实现收成一个实现点**（`scripts/lib/load-env.sh`），而不是把差异调平。调平只解决今天这两份；收成一个点让第三份不可能出现。

| 文件 | 动作 |
|---|---|
| `scripts/lib/load-env.sh` | **新增**。唯一的加载器实现。bash 3.2 语法（macOS 自带 `/bin/bash` 是 3.2.57，两个调用方的 shebang 都是 `#!/usr/bin/env bash`，所以不得使用 `declare -A`） |
| `scripts/dev-up.sh` | 删掉内联 `load_env_file()`（原 `:92-114`），改为 `source` + `load_env_snapshot` |
| `scripts/dev-local-start.sh` | 删掉两段内联循环（原 `:139-174`），改为 `source` + `load_env_snapshot`；`.env.dev` 改为可选；**补上 `MYSQL_DSN` 与 `APP_ENV` 的显式默认值** |
| `scripts/check-env-loaders.sh` | **新增**。17 条断言 |
| `scripts/dev-check.sh` | 在 `go build` 与缺陷纪律之间插入新断言 |

### 统一后的语义（每一条都有断言）

| 输入 | 结果 |
|---|---|
| `PLAIN=plain` | `plain` |
| `SPACED_KEY   =   spaced` | `spaced`（键与值都 trim） |
| `INLINE=abc  # 注释` | `abc` |
| `HASH_IN_VALUE=abc#def` | `abc#def`（`#` 前无空白 → 不是注释） |
| `QUOTED="quoted value"` | `quoted value` |
| `QUOTED_HASH="a # b"` | `a # b`（引号内的 `#` 不是注释） |
| `SINGLE='single'` | `single` |
| `QUOTED_THEN_COMMENT="v" # 注释` | `v` |
| `EMPTY=` | 空，且**已设置** |
| 两个文件都设 `DUP` | 后加载的胜 |
| shell 已导出 `PRESET`，文件也设 | **shell 胜** |
| `1BAD=1` / `BAD-KEY=2` | 警告并跳过 |
| 裸词行 `BOGUS` | 警告并跳过（旧实现会导出成 `BOGUS=BOGUS`） |
| 文件不存在 | 返回 1，不崩调用方 |

**优先级「shell > 后文件 > 先文件」是两个调用方注释里各自声称的语义**（`dev-up.sh`「Shell / --host / CI exports win」、`dev-local-start.sh`「Values here take precedence」）。此前两份实现各实现了其中一半：`dev-up.sh` 做到了「shell 胜」但后加载的文件压不过先加载的；`dev-local-start.sh` 做到了「后加载的胜」但压掉了 shell。**实现方式是 `load_env_snapshot` 在任何文件之前记下已导出的变量名**（存成一条空格包围的字符串，不用关联数组，为了 bash 3.2）。

## 未覆盖的部分（明确声明）

1. **Go 侧的第三个加载器没有合并。** `internal/voicegateway/config.go:431-462` 的 `loadDotenvIfPresent` 仍是独立实现，且与新的 shell 语义**仍有一处不同**：它不剥行内注释（shell 侧现在剥）。原因是它读的是同一批文件，而 shell 侧现在会剥注释——所以由 shell 启动时，Go 侧看到的是已解析好的值，**它自己的解析器实际上只在裸 `go run` 时生效**。合并它需要跨语言共享语义，属于 `105_` 的 **D2**（需要决策），本次不做。
2. **`SETUP.md` 与 `internal/voicegateway/{config,provider_factory}.go` 里对 `.env.dev` 的 4 处陈旧陈述没有改。** 它们是 `105_` 的 F1 的剩余面，性质是文档修正而非本接缝的修复；混进这一批会让「行为修复」与「文档修正」无法分离。见 `105_` §5。
3. **`105_` 的 F4–F9 全部未动。** 见 `105_` §4 的决策表。
4. **`dev-local-start.sh` 补上的 `MYSQL_DSN` / `APP_ENV` 默认值没有自动化测试**——它需要 MySQL + Redis 真的在跑。手动复现步骤：`./scripts/dev-local-start.sh`，预期日志里**不应出现** `MYSQL_DSN is empty; using in-memory ...`（出现即说明 DSN 没着落）。
