### F2 — `dev-local-start.sh` 必然失败，而那个硬失败是**承重的**（P1）

**第一层（表面）**：`dev-local-start.sh:154-157` 在 `.env.dev` 缺失时 `exit 1`。`dev-stack.zsh` 末尾 `exec` 它，所以两个脚本在干净克隆上都不可用。

**第二层（关键，读代码才看得到）**：**它全文不设置 `MYSQL_DSN`。**

`dev-local-start.sh` 在配置阶段只导出四件事（`:179-182`）：

```bash
export HTTP_ADDR="0.0.0.0:${PORT}"
export VOICE_GATEWAY_HTTP_ADDR="0.0.0.0:${GATEWAY_PORT}"
export VOICE_GATEWAY_WSS_URL="ws://${HOST}:${GATEWAY_PORT}/v1/voice"
export APP_SERVER_INTERNAL_URL="http://127.0.0.1:${PORT}"
```

**没有 `MYSQL_DSN`。** 它完全依赖 `.env.dev` 提供。

对照 `dev-up.sh`——在 MySQL 模式下是**显式**给的（`:197` / `:205`）：

```bash
export MYSQL_DSN="${MYSQL_DSN:-fw:fw@tcp(127.0.0.1:3306)/fluentwork?parseTime=true&charset=utf8mb4&loc=UTC}"
```

**所以**：那个 `exit 1` **挡住了更坏的结局**——MySQL 与 Redis 都在跑、健康检查全绿，而 app-server 因为拿不到 DSN 静默退回内存存储。用户在 `dev-local-start.sh` 这个「MySQL 栈」里跑，数据却全在内存里，重启即失。

**结论**：守卫的**意图是对的，依赖是错的**。

**所以「把 `.env.dev` 改成可选」这个显而易见的修法是错的**——它会把一个响亮的失败换成一个静默的错误。正确的修法必须同时补上 DSN，见 `106_`。

**确定性**：文件不存在与脚本行为是【实测】；「守卫挡住内存回退」是【读码】推出（`internal/config/config.go:122` 读 `MYSQL_DSN`，`cmd/app-server/main.go:276` 用它决定 worker 模式与存储）。

### F3 — 一份语义，三份实现（P1）

| 行为 | `dev-up.sh:92-114`<br>`load_env_file` | `dev-local-start.sh:142-174`<br>内联 `IFS='=' read` | `voicegateway/config.go:431-462`<br>`loadDotenvIfPresent` |
|---|---|---|---|
| 顶格 `#` 整行注释 | 跳过 | 跳过（靠 `grep -v '^#'`） | 跳过 |
| **缩进的 `#` 注释行** | **不跳过 → 见下** | **不跳过 → 见下** | 跳过（先 `TrimSpace` 整行） |
| **行内 `# 注释`** | **剥掉** | **不剥** | **不剥** |
| 值两端引号 | **不剥** | 剥 `"`（不剥 `'`） | 剥 `"` 与 `'` |
| 值两端空白 | 不 trim | 不 trim | **trim** |
| 键两端空白 | **trim** | **不 trim** | **trim** |
| 已存在的环境变量 | shell 胜 | **文件胜（覆盖）** | shell 胜 |
| 两个文件之间 | **先加载的胜** | 后加载的胜 | 后加载的胜 |

**「缩进注释行」那一格为什么会崩**（【推断】，由 bash 语义推出）：
`dev-local-start.sh` 的 `grep -v '^#'` 只挡顶格注释。一行 `  # 说明` 会走到 `IFS='=' read -r key value`，得到 `key='  # 说明'`，然后 `export "$key=$value"` → `export: not a valid identifier` → 在 `set -euo pipefail` 下**整个脚本退出**。

**最强的一条证据是文件自己写的**。`.env.volc.local` 头部（`4-9` 行）：

```
# ⚠️ 值里不要带行内注释。三个加载器里 scripts/dev-local-start.sh 用
#    `IFS='=' read` 逐行取，它只剥掉整行注释，不剥行内注释 ——
#    `KEY=abc  # 说明` 会变成以 "abc  # 说明" 为值，然后鉴权失败。
#    dev-up.sh 会剥，但别依赖这件事。
#
# ⚠️ 键不要用引号包起来：dev-up.sh 的 load_env_file 不剥引号。
```

**这就是 R7 要问的那个形状**：一个合法的 dotenv 写法（行内注释、带引号的值）会让系统以「鉴权失败」这种**远离原因**的方式坏掉，而修法是**在文件头写一段话让人不要那么写**。

**用文档规避代码缺陷，不是保护，是保护的样子。** 这与 `AGENTS.md` §7 点名的那个模式同类（「看起来有保护，实际没有」）。

**当前是否在发作**：【实测】**没有**。`.env.volc.local` 与 `configs/app-server.env.example` 都是**零行内注释、零引号键、零空格键、零缩进注释**。所以分歧是**潜伏的**——这也意味着现在统一它是**行为保持**的，见 `106_` 的验证一节。

### F5 — `cmd/app-server` 绕过 config 包（P2）

四个变量**在 `config.Load()` 之外**被读：

| 变量 | 位置 |
|---|---|
| `APP_RUN_REVIEW_WORKER` | `cmd/app-server/main.go:274` |
| `VOLC_SPEECH_API_KEY` / `VOLC_SPEECH_API_KEY_DEV` | `cmd/app-server/main.go:363` |
| `VOLC_SPEECH_RESOURCE_TTS` | `cmd/app-server/main.go:375` |

**两个后果**：

1. **它们不进 `Validate()`**。一个 typo 的 `APP_RUN_REVIEW_WORKER` 不会被任何东西拒绝。
2. **`104_03` §4.1 的「51 个变量」统计是漏的**——那四个不在任何 `Config` 结构体里，而该节说「唯一的清单是 `Config` 结构体本身」。

**更尖锐的一条**：`VOLC_SPEECH_API_KEY` 有**两个读取点、两套优先级**：

```go
// cmd/app-server/main.go:363
firstNonEmpty(os.Getenv("VOLC_SPEECH_API_KEY"), os.Getenv("VOLC_SPEECH_API_KEY_DEV"))

// internal/voicegateway/config.go:144-149
envFirst("VOICE_GATEWAY_VOLC_SPEECH_API_KEY", "VOLC_POC_API_KEY",
         "VOLC_SPEECH_API_KEY", "VOLC_SPEECH_API_KEY_DEV")
```

同一个 key，app-server 把 `VOLC_SPEECH_API_KEY` 排在 `_DEV` 之前，voice-gateway 把它排在 `VOLC_POC_API_KEY` **之后**。**当一个环境同时设了 `VOLC_POC_API_KEY` 与 `VOLC_SPEECH_API_KEY` 时，两个进程会拿到不同的 Key**，而失败症状是「TTS 偶发 401」——离原因很远。

### F6 — `intOr` 的注释承诺了代码没有的性质（P2）

```go
// internal/config/config.go:156-158
// intOr reads an integer setting. Unparseable or empty keeps the default;
// negatives are passed through so Validate can reject them loudly rather than
// have a typo quietly become a default.
func intOr(key string, fallback int) int {
	raw := strings.TrimSpace(os.Getenv(key))
	if raw == "" { return fallback }
	parsed, err := strconv.Atoi(raw)
	if err != nil { return fallback }        // ← 拼错的整数恰好静默变成默认值
	return parsed
}
```

注释后半句「rather than have a typo quietly become a default」**描述的是代码没做的事**：`DRILL_ROUND_SIZE=ten` 就是一个 typo，它**正是**静默变成了默认值 10。

`durationOr`（`:283-293`）同形状。

**而同一个仓已经写出了正确的做法**——在途新增的 `durationStrict`（`internal/voicegateway/config.go:353-371`）：

```go
// durationOr's silence is defensible where the fallback is also a defensible
// answer. It is not defensible for the ladder's spacing: an operator who writes
// VOICE_RESCUE_LEVEL1_AFTER=5 meaning five seconds, and gets three, has no way
// to find out — the same class of lie as a pricing file that fails to parse and
// leaves yesterday's rates in place
```

**所以这不是「不知道」，是「知道了但只改了 5 个变量」。** 剩下 ~12 个 typed 设置仍是旧的静默形状：

`DRILL_PROMOTE_STREAK`、`DRILL_TRAINING_INTERVAL`、`DRILL_AUTOMATED_INTERVAL`、`DRILL_AUTOMATED_REVIEW_INTERVAL`、`DRILL_FAIL_INTERVAL`、`DRILL_ROUND_SIZE`、`DRILL_DAILY_NEW_BLOCK_LIMIT`、`DRILL_OVERDUE_WINDOW`、`DRILL_JUDGE_TIMEOUT`、`TOPIC_MIN_BLOCKS`、`AUTH_ACCESS_TTL`、`AUTH_REFRESH_TTL`、`SESSION_TICKET_TTL`、`ARK_HTTP_TIMEOUT`。

**注意对称性**：`VOICE_GATEWAY_IDLE_TIMEOUT`（`voicegateway/config.go:162`）也走 `durationOr`，也就是**同一个文件里，救援梯子 5 个严格、idle timeout 1 个静默**。

**本次不动它**——因为它有两种修法（改成严格 = 行为变更；或改注释 = 承认现状），是**你的决定**，见 §4。

**确定性：【读码】。**

### F7 — 同一个包里两种「真」（P3）

```go
// cmd/voice-gateway/main.go:131
```

### F8 — `AppEnv` 无白名单（P3）

`internal/config/config.go:186-188` 与 `internal/voicegateway/config.go:212-214` 都只检查**非空**。

`isDevelopmentEnv`（`config.go:274-281`）认 `development/dev/test/local`；`IsProduction`（`:172-174`）认 `production`（大小写不敏感）。于是 `APP_ENV=prod`、`APP_ENV=staging`、`APP_ENV=developemnt`（拼错）都落在**两个都不是**的区间。

**为什么只有 P3**：失败方向是**安全的**。非开发分支更严——它会拒绝开发默认密钥（`:192-194`、`:213-215`）。所以拼错 `APP_ENV` 的后果是「启动失败」，不是「生产用了开发密钥」。**反向的那条路不存在**，这是这个设计做对了的地方。

剩下的成本只是**难懂**：一个拼错的 `APP_ENV` 报的是「AUTH_JWT_SECRET must be set outside development environments」，而真正的原因在另一个变量上。

**确定性：【读码】。**
