# 被打断的轮次：转录记用户**听到**的，不是 AI 生成的

**日期**：2026-09-11
**状态**：实现与测试已齐。**含一次数据库迁移。**
**对应**：meta `77_` **P1-14**

## 1. 决定（产品口径）

> **转录记"用户听到了什么"。**

这不是技术选择，是**产品选择**，而它决定了整票的形状：

- 选"AI 说了什么" → 被打断的回复**完整落库** + 一个标记位
- 选"用户听到了什么" → 被打断的回复**截断到打断点** + 一个标记位

选后者的理由：**转录是这个产品的学习资产**。一条记着用户从没听过的句子的转录，
会让回顾、徽章、复习这些下游全部建立在没发生过的事上。

## 2. 缺陷

`turnToOutbound` 里 AI 那条 utterance 用的是 `reply` —— **完整的回复**，
无论有没有被打断：

```go
s.utterances = append(s.utterances, EndUtterance{Seq: …, Speaker: "ai", Text: reply})
```

而网关**边生成边推流**，客户端在打断时把"在途"的音频帧按水位线丢掉。
所以：**用户听到了一部分，记录写的是全部。**

`interrupt` 到达时，两层各记一条日志即止 —— 不停止转发、不在会话记录里留痕。

## 3. 修法：截断 + 标记

**网关侧**（`provider_volc_duplex.go`）：

1. 新增 `deliveredText` —— 累积**实际推给客户端**的助手文本（在 `AssistantTextDelta` 里追加）
2. `interrupt` 到达时置 `interruptedThisTurn`
3. 轮末写 utterance 时：被打断 → `Text` 用 `deliveredText`，并带 `Interrupted: true`
4. **一点都没送达就不写这条 utterance** —— 用户什么都没听到，写一条空行等于说"助手说话了"

**app-server 侧**：迁移 `0016` 加 `utterances.interrupted`，两层类型各加字段，
`normalizeEndUtterances` 与 `mysql_store` 的 INSERT/SELECT 都带上它。

### 为什么"送达的文本"能代表"听到的"

文本与音频**同源同步生成**：TTS 按文本流推进，文本推送到客户端 ≈ 那段音频已经生成。
网关没有"文本↔音频"的时刻对应表，所以**送达文本是可得的最佳代理**。

**这句话要坦白说清**：它严格上界是"网关送出了什么"，而不是"用户耳朵收到了什么"
（两者差着客户端按水位线丢掉的那几帧）。但那几帧正是**因为用户打断才被丢的** ——
用户是否"听到"它们本来就是模糊的。**从"完整的回复"改成"打断点之前"，
是这一票能给出的、也是唯一诚实的近似。**

## 4. 测试

| 测试 | 守什么 |
|---|---|
| `TestInterruptedTurnRecordsOnlyWhatWasDelivered` | 打断后，utterance 只含**已送达**的部分、且带 `Interrupted` |
| `TestUninterruptedTurnRecordsTheWholeReplyAndNoFlag` | 未打断**逐字不变**，且**不置标记**（永远为真的标记不是标记） |
| `TestInterruptBeforeAnyDeliveryRecordsNoAssistantTurn` | 一点没送达 → **不写**这条 utterance |
| `TestBargeInStartThenInterruptStillRecordsWhatWasDelivered` | `user.speech.start` 在 collect 中不擦掉 `deliveredText` |
| `TestInterruptStopsForwardingFurtherAssistantAudio` / `…TextDeltas` | 打断后不再转发该轮剩余 TTS / 文本 |
| `TestHandler_ProcessesInterruptWhileSpeechEndIsCollecting` | `WaitTurnResult` 在飞时，读循环仍能处理 `interrupt` |
| `TestCollectTurn_DropsStaleResponseDeltasUntilThisTurnHasUserProgress` | 上一轮残留 delta 不拼进本轮回复 |
| `TestNormalizeEndUtterancesCarriesTheInterruptedFlag`（app-server） | 标记**过得了边界**，且不泄漏到没被打断的轮次 |

### 红验证（两次，各自咬住）

**网关**：把截断分支改成 `if false && s.interruptedThisTurn`：

```
--- FAIL: TestInterruptedTurnRecordsOnlyWhatWasDelivered
    the transcript recorded speech the user never heard:
    "Sounds good. But let me add something you never heard."
--- FAIL: TestInterruptBeforeAnyDeliveryRecordsNoAssistantTurn
    recorded an assistant turn for speech the user never heard: [{… Interrupted:true}]
```

**未打断那条保持绿** —— 破坏只影响被打断的路径，正是该有的互补。

**app-server**：把 `Interrupted: item.Interrupted` 改成 `false`：

```
--- FAIL: TestNormalizeEndUtterancesCarriesTheInterruptedFlag
    the interrupted flag was dropped at the boundary: {… Interrupted:false}
```

> 第二条测试存在的理由：**一个在边界被丢掉的标记，会让截断变成对记录的"静默编辑"
> 而不是"有说明的编辑"。** 网关截断了文本却没带标记，读的人会以为 AI 就说了那么短。

## 5. 影响面

| 维度 | 影响 |
|---|---|
| **数据库** | **一次迁移**（`0016`，含 down）。加列、有默认值，**对既有行无影响**（既有行 `interrupted=0`） |
| **协议** | 网关→app-server 的 `sessions/end` body 多一个可选字段（`omitempty`，旧网关不发也合法） |
| **转录内容** | **被打断的助手轮次从此更短** —— 这是**有意的**，也正是本票的目的 |
| **未打断的轮次** | **逐字不变** |

## 6. 未做

- **没有取消火山侧生成。** 上游没有 cancel API。打断后网关**停止转发**该轮剩余
  `output_text.delta` / `output_audio.delta`，并丢掉 `turnToOutbound` 里未发出的
  半帧；`collectTurn` 仍把火山事件读完（利于丢掉上一轮残留），计费仍按 vendor
  产出的 PCM。停的是客户端听到的，不是账单。
- **没有把 `interrupted` 暴露给客户端 API。** 列已经存在、读路径已经带上，
  但**回顾页 / 复习 / 徽章还没有读它** —— 那要各自由产品决定怎么呈现。
  **登记为未做**，免得有人以为已经显示了。
- **没有处理"音频比文本晚"的边界。** 见 §3 的坦白：代理是送达文本，不是耳朵。
- **没有把 `ai.tts.end.completion_status` 改成 `interrupted`。** iOS 枚举已有该值，
  网关仍按 turn outcome 填写。
