# 第二波 B15 离线评估集实现说明

**对应 issue**：#28（标题也叫 B15；**不是**语音网关 Turn Timeout 那张 B15）  
**代码**：`bdd94a6` `a869441`（本提交补数据集测试、口径说明与关单文档）  
**门禁**：`./scripts/eval-prompt-regression.sh`；`go test ./internal/eval/...`

## 原理与背景

技术方案 3.4 要求在接真实 LLM 之前先有离线评估集，用来卡住评价 / 炼化 Prompt 的回退。没有这套门禁，B8 只能靠 live smoke，改 Prompt 会静默变差。

#28 允许内测前用**合成 / 演示素材**，禁止把真实用户转录放进评估集。

## 方案

独立目录 `eval/offline/`，不进生产链路。

| 部件 | 作用 |
| --- | --- |
| `eval/offline/samples/wave2-synth-v1.json` | 103 条合成样本（5 个 scene） |
| `internal/eval` | Schema、原句引用、炼化三元组、封闭标签 |
| `cmd/eval-prompt-regression` | 一条命令跑全集，失败打 `sample_id` + `rule` |
| `cmd/gen-eval-samples` | 可复现生成 100 条合法样本 |
| `scripts/eval-prompt-regression.sh` | `go test` 判定器 + 生成器自检 + 跑 JSON |

`reviewgen.Generate` 对模型输出调用同一套 `ValidateSample`，所以离线绿和线上校验是同一规则。

「好 / 坏」口径：转录是带语病或卡壳的学员话，refine 是合格三元组。**预期失败的规则用例只放在单测里**，基线 JSON 必须全绿，否则改 Prompt 无法分辨是规则坏了还是样本坏了。

## 缺口根因

票面写评估集「当前缺失」时，第一波还没有 `internal/eval`。后来 `bdd94a6` / `a869441` 已经把 103 条合成样本和脚本合进 `main`，但 #28 未关，`docs/05` 仍写「后续扩到 50–100」。数量早已达标，缺的是关单说明和「`go test` 直接读这份 JSON」的哨兵。

## 新方案理由

- **合成样本而不是等标注**：B8 提测不能堵在真人标注上；票面允许演示素材。
- **基线只收合法样本**：回归要全绿；坏路径用单测钉死 quote / 非法 tag。
- **生成器可复现**：手写 100 条 JSON 容易和校验器漂移；`gen-eval-samples` 按 scene frame 构造，单测要求每条都能过 `ValidateSample`。
- **与语音 B15 分文档**：#28 是 Prompt 质量门；`docs/23` 是 WSS turn timeout。不要混进 AGENTS 的 B15 行。

## 明确不做

- 真实用户转录、发音评测样本、Prompt 灰度中心
- 把评估集打进 worker / app-server
