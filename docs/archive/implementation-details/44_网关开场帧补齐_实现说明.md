# volc-duplex 会话补齐 bootstrap `ai.turn.end`

**对应**：真机火山日志回溯（session `cbfa2d23`，2026-09-10）。I20 Item 4 手动开口路径的相位错配。  
**代码**：`internal/voicegateway/provider_volc_duplex.go`（`volcDuplexProviderSession.Start`）  
**门禁**：`./scripts/dev-check.sh` → All checks passed；`go test ./...` 23 包全绿

## 原理与背景

**每条 provider 会话在 `Start` 后都必须发一条 bootstrap `ai.turn.end`，作为「会话已开、可以开口」的信号。**

iOS 状态机在 `socketReady` 时就进入 `aiSpeaking`（`connecting --socketReady--> aiSpeaking`），而离开 `aiSpeaking` 只有一条路：`aiTurnEnd`。没有这条帧，客户端会一直以为 AI 正在说话。

## 缺口根因

`MockVoiceProvider` 与 `DevEchoVoiceProvider` 的 `Start` 都返回两条 bootstrap 出站帧（`ai.text.delta` + `ai.turn.end{turn_id:"bootstrap"}`）；**只有 `VolcDuplexProvider` 返回 `nil, nil`**：

```go
// 旧实现
	s.session = session
	s.nextSeq = 1
	if s.nowFn == nil {
		s.nowFn = time.Now
	}
	return nil, nil          // ← 不发任何开场帧
}
```

后果链：iOS 连上后永远停在 `aiSpeaking` → 用户第一次点「开始说话」被状态机判为 **barge-in**（`aiSpeaking --vadSpeechStart--> recording` + `.stopPlayback` + `.sendInterrupt`）→ 网关收到 `interrupt`。

真机日志正好是 1ms 的间隔：

```
21:47:14.097  voice user speech frame  type=user.speech.start
21:47:14.098  interrupt received
21:47:14.098  interrupt forwarded to live provider boundary
```

`interrupt` 在 volc provider 里是**空操作**（只打一条日志），所以用户没有可感损伤——但这是**只在真机火山路径上出现**的相位错配：DevEcho 会发开场帧，所以模拟器与 Phase 1 都测不出来。

## 方案

`Start` 成功后返回一条出站帧：

```go
return []ProviderOutbound{{
	Control: voiceproto.AITurnEnd{
		Type:    voiceproto.TypeAITurnEnd,
		TurnID:  "bootstrap",
		Outcome: "ok",
	},
}}, nil
```

形状与 DevEcho 的开场帧一致（`turn_id: "bootstrap"` + `outcome: "ok"`），iOS 早已有对应处理与测试。

### 两个刻意的「不带」

| 不带 | 原因 |
|---|---|
| `log_id` | iOS 的 `SpeechSessionTimingsRecorder.setLogID` 是 **per-session 首次非空、不覆盖**。`client.turn.abort` 会 `resetDuplex` 重建一条新 duplex（新的 `X-Tt-Logid`），若开场帧先把旧 duplex 的 id 占住，第一轮真实 turn 的 `log_id` 就进不去，`docs/35` 建立的 `turn_id`+`log_id` 配对会错位。 |
| `ai.text.delta` | DevEcho 的 `"ready"` 是 stub 文案，在 dev provider 上无妨；真实会话伪造助手文本会出现在用户可见的 transcript 里。开场帧只表达「可以开口」，不替模型说话。 |

## 新方案理由

- **不折进 `HandleClientControl`**：会话开启是 `Start` 的事件，与任何客户端控制帧无关；塞进别处会让「谁负责开场」变得不可读。
- **不改 iOS**：iOS 的 greeting 分支（`aiSpeaking + aiTurnEnd` 且 `userTurnCount == 0` → `waitingUser`）已存在且有测试（`bootstrapAITurnEndOutcomeOkReturnsToWaitingUser`）。缺的是网关没发，不是客户端没处理。
- **不新增帧类型**：复用既有 `ai.turn.end`，iOS 无需改解码。

## 影响面

- **协议**：**不改形状、不加字段、不动 v1/v2 schema**。变的是 volc 路径上 `ai.turn.end` 的**出站时机**——多一条 turn 开始时的 bootstrap 帧。冻结期白名单里「禁止改动 `ai.turn.end` 形状」不适用；但这是**可观测行为变化**，须与 iOS 一起回归。
- **状态**：iOS 连上后落在 `waitingUser`（而非 `aiSpeaking`）。首次点按不再走 barge-in，不再发 `interrupt`。
- **音频**：首次点按不再触发 `.stopPlayback`。此时本就没有播放，无实际差异。
- **客户端回归点**：真机上确认 (a) 开场后 UI 显示「可以开口」而不是「AI 说话中」；(b) 首轮不再出现 `interrupt` 出站帧；(c) AI 真正说话时（首个音频块到达）仍能 barge-in。
- **发布**：无迁移、无配置项。

## 明确不做

- 不做真正的**开场白内容**（让模型主动说第一句）。那需要另设计一次「开场触发」，属于 turn 合同变更，不在本票。
- 不动 Mock / DevEcho 的既有开场帧。
- 不改 iOS 状态机（`socketReady → aiSpeaking` 的落点保持原样）。
