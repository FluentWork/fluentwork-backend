# 取消不是断连：读错误的分类收窄

**日期**：2026-09-11
**状态**：实现与测试已齐。
**对应**：meta `77_` **P1-11**

## 1. 为什么

`voicepoc.collectTurn` 的读错误只区分一种情况：

```go
if errors.Is(err, context.DeadlineExceeded) {
    // 优雅降级：捞出已有的内容
} else {
    out.Outcome = TurnOutcomeError
    collectErr = fmt.Errorf("%w: %w", ErrDuplexClosed, err)   // ← context.Canceled 也走这里
}
```

而 `ErrDuplexClosed` 的消费方**会重置整个 duplex**：

```go
// provider_volc_duplex.go
if errors.Is(err, voicepoc.ErrDuplexClosed) {
    s.resetAfterTurnReadFailure(ctx)
}
```

于是**调用方主动取消**与**套接字真的死了**被并成同一类。

## 2. 为什么这算缺陷 —— 它和同一份代码的立场不一致

就在那个 `if` 的**上方三行**，注释写着：

> A provider error *event* is different: the session is still usable and resetting would discard the server-side conversation context.

也就是说，这份代码**已经**在区分"会话还能不能用"了，而且明确把"重置会丢弃服务端上下文"当成代价。可它同时又让 `context.Canceled` 走进了重置分支 —— **分类粒度与它自己的立场对不上**。

`context.Canceled` 的含义是**调用方撤了**（客户端断开、会话正在收尾）。socket 没有死；重置一个健康的 duplex，代价是丢掉一段可能还要继续的服务端上下文。

## 3. 影响面：不紧急，但它让一个问题失去了答案

生产上 `HandleClientControl` 拿到的是 WSS handler 的 ctx，客户端断开时取消 —— **那种情况下 reset 无害**（会话本来就要结束）。

所以这不是一个会造成用户可见故障的缺陷。真正的代价是**分类学的**：

> **"哪些情况该 reset？"这个问题失去了精确答案。**

每一个"调用方走了"都会看起来像一具尸体。而下一个要在这个函数里做判断的人（比如"要不要给取消也加个重试"、"这个 reset 是不是多余"）拿不到可用的信号。

## 4. 修法

新增一个 sentinel，把取消从"断连"里摘出来：

```go
var ErrTurnCancelled = errors.New("turn cancelled by caller")
```

```go
} else if errors.Is(err, context.Canceled) {
    out.Outcome = TurnOutcomeError
    collectErr = fmt.Errorf("%w: %w", ErrTurnCancelled, err)
} else {
    out.Outcome = TurnOutcomeError
    collectErr = fmt.Errorf("%w: %w", ErrDuplexClosed, err)
}
```

**`ErrDuplexClosed` 的语义因此变纯**：它现在只表示"套接字死了"，正是 `resetAfterTurnReadFailure` 该被调用的那一种。调用方 `errors.Is(err, voicepoc.ErrDuplexClosed)` **一个字没改**就自动不再对取消重置。

`outcome` 仍是 `error`（两端都不该被当成超时），变的是**错误的分类**。

## 6. 未做

- **没有给"取消"加新行为**。本票只修分类：`collectTurn` 的 outcome 仍是 `error`，是否重试、是否上报由调用方决定，而本票**没有改变任何调用方的行为**（唯一的自动变化是 provider 不再对取消重置 —— 那正是目的）。
- **没有动 `DeadlineExceeded` 的分支**。超时是另一回事（等窗口走完），行为与分类都不变。
- **provider 层的守卫没加**。分类测试是本票的复现与守卫；"provider 不重置"是从 `errors.Is` 直接推出的，且那一段没有可注入的 duplex 替身。若将来要钉住 provider 层的行为，需要先做一个可注入的 provider session 替身。
