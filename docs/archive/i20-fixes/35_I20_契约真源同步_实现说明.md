# I20 契约收口（infra v2 真源）

**对应**：docs/33 / docs/34 写明的「另票」——把已上线的 speaking-room 合同写回 `fluentwork-infra`。  
**代码**：`fluentwork-infra` `d60d0fe`（canonical v2）；本仓 mirror 已与真源一致，未再改 JSON。  
**门禁**：infra `bash scripts/check-repo-structure.sh`；本仓 `go test ./internal/voiceproto/...`（schema embed 仍绿）

## 原理与背景

`fluentwork-infra` 才是 WSS schema 真源。backend / iOS 各持一份 mirror，靠 `scripts/sync-shared-schemas.sh` 向外拉。

B15 的 `ai.turn.end.outcome` / `log_id` 和 I20 的 `client.turn.abort` 先落在运行时仓。真源仍是旧 v2 时，下一次 iOS/backend sync 会把这两处盖掉。

## 方案

infra v2 与 backend `5c2e39f` 对齐：

- `$defs.clientTurnAbort` + `oneOf` 引用；`outcome` 仅 `timeout|user_abandoned|error`；无 `session_id`
- `$defs.aiTurnEnd` 可选 `outcome`（`ok|partial|timeout|error`）和 `log_id`
- **v1 不动**（冻结快照）

本仓与 iOS mirror 在 sync 前已经逐字节相同，所以没有第二次 JSON 提交。

## 缺口根因

运行时仓先发协议、真源后补。sync 脚本默认方向是 **infra → 运行时**，真源落后就会回滚已发布字段。

## 新方案理由

先改 canonical 再 sync，而不是继续在三仓各改一份 v2。v1 仍不当作现行 speaking room 合同。

## 明确不做

- 不改 v1
- 不在本提交改 iOS（T-I20 与 wire fixture 已在 iOS `main`）
- 不把 I20 计划里的 Item 4 手动 VAD 算进这张收口（那是 iOS P1，与 abort 协议无关）
