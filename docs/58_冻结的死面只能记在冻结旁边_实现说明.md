# 冻结的死面：连注释都写不进去，所以记在冻结旁边

**日期**：2026-09-11
**状态**：实现与测试已齐。
**对应**：meta `77_` **P1-18**

## 1. 为什么

v1 的 WSS 控制帧 schema 里有两个**从来没有跑过**的面：

| 面 | 实况 |
|---|---|
| `ai.audio.chunk` | 后端只有一个常量声明（`frames.go:21`），**全仓再无一处引用** —— 连测试都没有 |
| `interrupt.max_seq` | 后端 `MaxSeq *int64 \`json:"max_seq,omitempty"\`` **从没被赋值**；**客户端根本不解码它**（iOS 的 `interrupt` case 没有任何载荷） |

两者都**字节冻结在 v1**，删不掉。

## 2. 第一个尝试失败了 —— 而且失败得很有价值

按通常做法，我在 schema 里给这两个面加了 `description`（JSON Schema 的注解，不影响校验）：

```json
"max_seq": {
  "description": "FROZEN, AND NEVER RAN. ...",
  "type": "integer", "minimum": 0
}
```

**门禁直接否掉：**

```
--- FAIL: TestSchemaV1BytesAreFrozen (0.00s)
    frames_test.go:434: v1 WSS schema is frozen; revert schemas/transport/wss-control-frames-v1.json
    (got e48007dcac4e6ee64f2403d4fca6b440f484da56f2b439f9d4e83ce0dbbcb364
     want bdb0324ca88839d86fd02b9f807de8f27f5ffcd7174857554873d6e8ff24e683)
```

**v1 是按 SHA-256 冻结的。** 这比"删不掉"强得多 —— **连加一条注释都做不到。**

这条比票面本身更值得记：台账说的是"**现在删不掉**"，实测是"**一个字节都动不了，包括解释它为什么动不了的那句话**"。

## 3. 所以记录只能落在约束旁边

既然 schema 文件不可变，记录就放在**执行冻结的那个测试文件里** ——
一个想知道"`ai.audio.chunk` 到底是不是活的"的人，顺着"为什么我不能改这个文件"找过来，就会落在这里。

`TestSchemaV1DeadFacesAreStillPresentAndStillDead` 做两件事：

**一、断言两者仍在**（冻结在生效）。它失败时的信息**就是提醒本身**：

```go
t.Fatal("v1 interrupt.max_seq is gone: it is frozen bytes and cannot be removed; see the P1-18 note above")
```

**二、断言两者仍然死** —— 对零值 `Interrupt` 做 marshal，必须**不含** `max_seq`：

```go
if strings.Contains(string(raw), "max_seq") {
    t.Fatalf("interrupt now serialises max_seq (%s) — if something started "+
        "setting it, the P1-18 note above needs updating rather than deleting", raw)
}
```

第二条是"**声明了但没人赋值**"从外面看的样子。它不会因为有人开始赋值而失败 ——
它失败是**提醒那条注释该更新了**，而不是阻止赋值。这一点写在失败信息里，免得下一个人把它当护栏。

## 4. 测试

```bash
./scripts/dev-check.sh      # All checks passed.
```

### 红验证（模拟一次"v1 清理"）

把 `max_seq` 从 schema 里删掉、**并同步更新冻结哈希**（这正是真做清理的人会走的路径）：

```
--- FAIL: TestSchemaV1DeadFacesAreStillPresentAndStillDead (0.00s)
    frames_test.go:487: v1 interrupt.max_seq is gone: it is frozen bytes and cannot be removed;
    see the P1-18 note above
```

红的正是预料的那条，且失败信息把原因和去处都说了。恢复后全绿。

## 5. 教训（票面结论的加强版）

台账原本的教训是"**冻结之前先跑一遍**"。实测把它推得更远：

> **v1 是一次承诺。对一个没人执行过的代码做的承诺，是对"无"做的承诺 —— 而且它是不可撤销的。**

代价在这两处体现得很具体：`ai.audio.chunk` 让**每一个**读 schema 的人多知道一件不存在的事
（"音频有两条路径，一条文本、一条二进制"），而它连一个生产者都没有。

**可迁移的判据**：冻结一个面之前，问的不是"这个字段设计得对吗"，而是
**"有没有一条测试构造过它"**。没有，就不该冻。

## 6. 影响面

| 维度 | 影响 |
|---|---|
| **协议 / schema** | **零改动**。v1 一个字节没动（改不动）—— 这也是本票的发现 |
| **运行时行为** | 零改动。只加测试与注释 |
| **infra 仓** | **无改动**。sync 脚本拉的是 infra 的源，而源同样不可改；本次对 infra 的尝试已回滚 |
| **可发现性** | 两个死面的"为什么还在这儿"现在写在**冻结点旁边**，而不是一个打不开的文件里 |

## 7. 未做

- **没有删任何东西**，也删不掉（§2）。
- **没有把记录写进 schema**。试过了，被哈希挡下；这不是待办，是这条路不存在。
- **没有给 `ai.audio.chunk` 加第二条断言**（比如"常量必须存在"）。常量存在与否不改变它是不是死的 ——
  而真正要防的"有人以为它是活的"，已经由这段注释承担。
