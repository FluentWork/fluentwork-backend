# FluentWork Backend 本地启动

**定位**：本仓本地开发的一键启动说明。产品与技术方案仍以 `fluentwork-meta` 为准。

## 默认启动（内存存储，无需 Docker）

需要：Go 1.26+。

```bash
./scripts/dev-up.sh
```

脚本会：

1. 读取 `.env`，没有则读取 `configs/app-server.env.example`
2. 清空 `MYSQL_DSN`，使用进程内账号/会话存储
3. 启动 `app-server`，并默认启动 `voice-gateway`（可用 `--no-gateway` 关闭）
4. 等待双方 `/healthz`，并请求一次 `POST /api/v1/auth/guest`

默认地址：

- app-server：`http://127.0.0.1:8080`
- voice-gateway：`ws://127.0.0.1:8081/v1/voice`

停止：在该终端按 `Ctrl-C`。

## 可选：带 MySQL 8 启动

需要本机 Docker daemon 可用。

```bash
./scripts/dev-up.sh --mysql
```

这会通过 `deploy/docker-compose.yml` 拉起 MySQL，并按文件名顺序执行 `migrations/*.sql`。

停止 MySQL：

```bash
./scripts/dev-down.sh
```

## 常用接口

鉴权头：`Authorization: Bearer <access_token>`  
错误体：`{code, message, request_id}`  
API 前缀：`/api/v1`

```bash
# 健康检查
curl -sS http://127.0.0.1:8080/healthz
curl -sS http://127.0.0.1:8080/readyz

# 签发或复用游客身份（device_id 幂等）
curl -sS -H 'Content-Type: application/json' \
  -d '{"device_id":"device-1"}' \
  http://127.0.0.1:8080/api/v1/auth/guest

# 归并游客数据到已注册账号（需要非游客 access token）
curl -sS -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -d '{"device_id":"device-1"}' \
  http://127.0.0.1:8080/api/v1/account/merge
```

第一波 B1 不含完整邮箱/手机登录。merge 的注册账号由后续登录接口或测试夹具创建。

契约见 `api/openapi-v1.yaml`，运行时也可通过 `GET /openapi.yaml` 拉取。

## 配置

| 变量 | 说明 |
|---|---|
| `APP_ENV` | `development` 或 `production` |
| `HTTP_ADDR` | 监听地址，默认 `:8080` |
| `MYSQL_DSN` | 空则内存存储；生产环境必填 |
| `AUTH_JWT_SECRET` | 至少 32 字符；生产环境必须覆盖开发默认值 |
| `AUTH_ACCESS_TTL` | access token 有效期，默认 `2h` |
| `AUTH_REFRESH_TTL` | refresh token 有效期，默认 `720h` |
| `VOICE_GATEWAY_WSS_URL` | `POST /sessions` 返回的 WSS 地址，默认 `ws://127.0.0.1:8081/v1/voice` |
| `SESSION_TICKET_TTL` | WSS 票据有效期，默认 `60s` |
| `INTERNAL_API_TOKEN` | app-server ↔ voice-gateway 内部调用共享密钥（开发默认值仅限本地） |
| `VOICE_GATEWAY_HTTP_ADDR` | voice-gateway 监听地址，默认 `:8081` |
| `APP_SERVER_INTERNAL_URL` | voice-gateway 调用 ticket consume 的 app-server 基址，默认 `http://127.0.0.1:8080` |

复制示例：

```bash
cp configs/app-server.env.example .env
```

`.env` 已被 gitignore，不要提交密钥。

## 契约发现（给 iOS / 前端）

启动 `app-server` 后可直接拉取：

## 会话创建（B2）

```bash
# 先拿游客 token
TOKEN=$(curl -sS -H 'Content-Type: application/json' \
  -d '{"device_id":"device-1"}' \
  http://127.0.0.1:8080/api/v1/auth/guest | python3 -c 'import sys,json; print(json.load(sys.stdin)["access_token"])')

# 创建 session，拿到 wss_url + ticket
curl -sS -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"scene_type":"demo"}' \
  http://127.0.0.1:8080/api/v1/sessions
```

## WSS 握手（B3）

契约 schema：`api/wss-control-frames-v1.json`

最小回路：

1. `POST /sessions` 拿到 `wss_url` + `ticket`
2. 连接 `ws://127.0.0.1:8081/v1/voice`
3. 首帧发送 `{"type":"auth","ticket":"..."}`
4. 网关调用 app-server `POST /internal/v1/tickets/consume`（头：`X-Internal-Token`）一次性消费票据
5. 收到 `{"type":"session.ready","session_id":"..."}` 后可发 `session.start` / `interrupt` / `session.end`

B3 不接火山引擎；`session.start` 会回一条 stub `ai.text.delta`。会话落库与 review 在 B4/B5。

## session.end 落库（B4）

网关在收到 `session.end` 后调用：

1. `POST /internal/v1/sessions/activate`（`session.start` 时）
2. `POST /internal/v1/sessions/end`（携带 `duration_sec` + `utterances`）

会把 `practice_sessions.status` 置为 `ended`，并写入 `utterances` 表（迁移 `0004_create_utterances.sql`）。重复 `end` 幂等。异步 review 投递仍属 B5。

## Review worker（B5）

`session.end` 成功后会向 `session_jobs` 投递 `session.finished`（迁移 `0005_create_session_jobs.sql`）。

```bash
go run ./cmd/worker
```

Worker 轮询 outbox，写入 stub `review_json`，并将 status 置为 `reviewed`（失败重试 1 次）。真实 LLM / Redis Stream 后续替换。

## Review 轮询（B6）

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8080/api/v1/sessions/$SESSION_ID/review"
```

返回 `status`：`pending`（未就绪）/ `ready`（含 `review` 文档）/ `failed`（outbox 永久失败）。仅会话所有者可查；非所有者与不存在统一 `NOT_FOUND`。

## 降级文本消息（B7）

语音优先时不带 `channel` 或非 `text` 会返回 `409 CONFLICT`。显式 `channel: text` 时返回 stub AI 回复（`generator: stub-text-v1`）。仅会话所有者可发；会话需为 `created` / `active`。

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text":"hello","channel":"text"}' \
  "http://127.0.0.1:8080/api/v1/sessions/$SESSION_ID/messages"
```
