## 2. TTS 帧

### 2.1 ai.tts.start 帧(gateway → client)

**触发**: gateway 即将推送 TTS 音频流, 用于客户端预热解码器。

| 字段 | 类型 | required | 默认值 | 说明 |
|---|---|---|---|---|
| type | const "ai.tts.start" | ✅ | "ai.tts.start" | 帧类型常量 |
| turn_id | string | ✅ | (无) | 与 ai.text.delta 一致 |
| voice_id | string | ✅ | (无) | 音色标识, 取自 voices.go 4 个常量 |
| sample_rate | int (Hz) | ✅ | 24000 | 火山 TTS 默认采样率 |
| codec | enum ["opus", "pcm"] | ✅ | "opus" | 音频编码格式 |

#### JSON Schema 草案

```json
{
  "type": "object",
  "required": ["type", "turn_id", "voice_id", "sample_rate", "codec"],
  "additionalProperties": false,
  "properties": {
    "type": { "const": "ai.tts.start" },
    "turn_id": { "type": "string", "minLength": 1 },
    "voice_id": { "type": "string", "minLength": 1 },
    "sample_rate": { "type": "integer", "enum": [16000, 24000, 48000] },
    "codec": { "type": "string", "enum": ["opus", "pcm"] }
  }
}
```

#### iOS 端集成示例

```swift
case "ai.tts.start":
    let start = try decoder.decode(AITTSStart.self, from: data)
    try ttsDecoder.prepare(
        voiceId: start.voice_id,
        sampleRate: start.sample_rate,
        codec: start.codec
    )
```

### 2.2 ai.tts.audio 帧(gateway → client, WebSocket binary message)

**触发**: `ai.tts.start` 之后持续推送音频 chunk, 直到对应的 `ai.tts.end`。

`ai.tts.audio` 不使用 WebSocket text message, 也不把音频编码为 JSON/base64。每条
WebSocket binary message 直接使用下列布局, 与 iOS
`WSAudioFrameCodec` 的现有实现一致:

| offset | 长度 | 字段 | 类型 | required | 说明 |
|---|---|---|---|---|---|
| 0 | 4 bytes | seq | UInt32, big-endian | ✅ | 从 0 开始, 在 gateway session 内严格单调递增 |
| 4 | 剩余 bytes | payload | binary | ✅ | 编码与采样率继承对应 `ai.tts.start` 的 `codec` / `sample_rate` |

#### 流关联与顺序约定

- `turn_id`、`voice_id`、`sample_rate`、`codec` 只在 `ai.tts.start` 控制帧定义,
  binary message 不重复携带。
- V2.0 固定单声道。`codec=pcm` 时 payload 必须是 PCM signed 16-bit
  little-endian mono；`codec=opus` 时 payload 必须是单声道 Opus packet。
- `ai.tts.start` 与对应 `ai.tts.end` 之间只允许一个活动 TTS 流, 不交错发送不同
  turn 的音频。
- 此处 gateway session 指单条已认证 WebSocket 连接。首条 binary message 的
  `seq` 为 0, 后续跨 turn 逐帧加 1, 不允许回绕。WebSocket 保证消息按发送顺序到达；
  iOS 使用 `seq` 维护 interrupt watermark, 本版本不声明通用乱序重排或去重。
- gateway 不得发送空 `payload`。最后一个音频 chunk 之后必须发送 `ai.tts.end`。

#### 帧时长

- 每条音频 message 的目标帧时长应为 20ms。
- 16kHz / 24kHz / 48kHz 单声道每帧分别是 320 / 480 / 960 samples。
- Opus payload 长度可变, 不以固定字节数作为帧边界；WebSocket message 自身即为边界。

#### iOS 端集成示例

```swift
case let .data(data):
    let frame = try WSAudioFrameCodec.decode(data)
    try ttsDecoder.feed(
        seq: frame.sequence,
        bytes: frame.opusPayload
    )
```
