# 未知帧忽略 + v1 schema 字节冻结

**对应**：进度报告审核 P0（meta `67_` V1.1）。**不是** B15 网关 timeout，也不是 B15 #28 Prompt 回归集。  
**代码**：`handler.go` 对未知 `type` 忽略并计数；`TestSchemaV1BytesAreFrozen` 钉死 v1 JSON SHA-256。  
**门禁**：`go test ./internal/voicegateway/... ./internal/voiceproto/...` 与全仓 `./scripts/dev-check.sh`

## 原理与背景

`client.turn.abort` 曾走 `default` → `unsupported_frame` → iOS `.failed`，真机录满 60s 打死活会话（`5c2e39f`）。那次只把 abort 加进白名单。`default` 仍回 error 帧，未来 v3 再加客户端帧，旧网关会用同一死法杀会话。

v1 也曾被误加 `outcome` / `log_id`（`docs/33`）。字段级单测能挡住那两处，挡不住「再往 v1 塞别的键」。直推 `main`、无 PR 时，纪律必须是 CI 字节钉死。

## 方案

| 项 | 做法 |
| --- | --- |
| 未知 `type` | 合法 JSON 且 `type` 非空但不认识 → `logWarn(unknown_frame)` + `rt.unknownFrameCount++`，**不**发 error 帧、不转 provider。随后 `ping` 仍回 `pong`。 |
| 非法帧 | 坏 JSON / 缺 `type` 仍 `invalid_frame`。已知类型的语义错误（abort `outcome=ok`、重复 auth）不变。 |
| v1 冻结 | `sha256(schemas/transport/wss-control-frames-v1.json)` 必须等于测试常量。失败信息要求 **revert JSON**，不要为了新字段去改 digest。新字段只进 v2。 |

版本协商：**本票不做。** speaking room de facto 全是 v2；`session.start` 没有 version 字段。写进 meta `67_` V1.1，真有旧客户端再开票。

`interrupt` **本票不实现 TTS 打断**。handler 仍转发，Volc 仍空操作。语义表进 `67_`，行为变更另票。

## 缺口根因

把「认识 abort」当成「未知帧策略」。白名单只能修个案。v1 冻结停在字段断言，文件其余部分仍可改。

## 新方案理由

- 不发 `unsupported_frame`：iOS 把任意 error 帧映射成 `.failed`。
- 不把未知帧转成 `interrupt` / `abort`：类型必须显式，不能猜。
- 不在本票加 `session.start.protocol_version`：冻结期只补机械防线，不改 turn 合同。

## 明确不做

- 不改 v1 JSON（改了 digest 测试会红，这是故意的）
- 不实现真正的 barge-in / 清火山缓冲 / `server_ts_ms` 校准
- 不在本仓改 iOS
