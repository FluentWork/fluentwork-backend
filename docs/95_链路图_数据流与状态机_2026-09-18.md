```mermaid
        BE["BadgeEmitter<br/>B7 命中检测"]
    end

    subgraph AS["app-server :8080"]
        RESCUE["/internal/v1/rescue/ladder<br/>梯子文本（模型）"]
        TTS["/internal/v1/tts/synthesize<br/>梯子音频（TTS）"]

        SESS["/internal/v1/sessions/*<br/>激活/结束/上下文"]
    end

    VOLC["火山引擎<br/>Duplex WSS"]
    ARK["火山方舟<br/>doubao"]

    MIC -->|"二进制帧"| LOOP
    LOOP -->|"PCM 上行 20ms/块"| VOLC
    VOLC -->|"文本 delta + 音频"| LOOP
    LOOP -->|"ai.text.delta / ai.tts.* / ai.turn.end"| GATE
    GATE --> PLAY
    PLAY -.->|"打断水位"| GATE

    POL -->|"沉默 3/6/9s"| RESCUE
    RESCUE -->|"梯子文本"| POL
    POL --> TTS
    TTS -->|"PCM 16k"| POL
    POL -->|"ai.rescue.ladder + ai.tts.*"| LOOP

    BE -->|"命中"| HITS
    BE -->|"feedback.badge"| LOOP
    LOOP --> SESS
    RESCUE --> ARK
    TTS --> VOLC
```

**一次说话里，音频和文本走的是两条不同的路**：

| 方向 | 载体 | 路径 |
|---|---|---|
| 上行音频 | 二进制帧 | iOS → gateway → 火山（每 20ms 一块，`voiceduplex.pcm16kChunkBytes=640`） |
| 下行 AI 语音 | 二进制帧 | 火山 → gateway（**重采样 24k→16k**）→ iOS（每 100ms 一块，`AudioFormat.FrameBytes(ClientFrameMS)=3200`） |
| 下行控制 | JSON 文本帧 | `ai.text.delta` / `ai.turn.end` / `feedback.badge` / `ai.rescue.ladder` |
| 梯子音频 | 二进制帧 | app-server TTS → gateway → iOS（**复用下行 AI 语音那条路**） |

## 三、会话状态机（gateway 侧）

`sessionRuntime` 没有显式的状态枚举，状态由若干字段共同表达。这是**现状**，也是 `94_` F1 说的那件事。

```mermaid
stateDiagram-v2
    [*] --> Handshaking: WSS 升级成功
    Handshaking --> Idle: ticket 消费成功
    Handshaking --> [*]: 认证失败 / 无 ticket

    Idle --> Started: session.start<br/>成功 Open provider
    Idle --> [*]: 读超时（idleTimeout）

    Started --> Started: 控制帧（转发 provider）
    Started --> Collecting: user.speech.end<br/>collecting.CAS(false→true)
    Collecting --> Started: collect 完成<br/>collecting.Store(false)

    Started --> Broken: 上行音频转发失败且 reopen 用尽
    Collecting --> Broken: 同上
    Broken --> [*]: 发 error 帧后立即退出

    Started --> Persisted: session.end<br/>或连接关闭
    Collecting --> Persisted: 同上
    Persisted --> [*]

    note right of Broken
        reopenAttempted 在 user.speech.start 时重置
        → 每个 turn 一次透明重开预算
    end note
```

**字段与状态的对应**（现状的"状态在哪儿"）：

| 状态 | 由什么表达 |
|---|---|
| 未开始 | `!rt.started` |
| 已开始 | `rt.started == true` |
| collect 中 | `rt.collecting`（`atomic.Bool`） |
| 已损坏 | `rt.broken`（普通 bool，只写一次） |
| 已持久化 | `rt.ended` |
| 重开预算 | `rt.reopenAttempted` |

## 四、turn 状态机（provider 侧）

```mermaid
stateDiagram-v2
    [*] --> NoTurn
    NoTurn --> TurnOpen: user.speech.start /<br/>首个文本 delta
    TurnOpen --> TurnOpen: 文本 delta / 音频块
    TurnOpen --> TurnClosed: response.done /<br/>ai.tts.end
    TurnClosed --> TurnOpen: 下一轮
    TurnOpen --> Aborted: client.turn.abort /<br/>interrupt
    Aborted --> TurnOpen: 下一轮

    note right of TurnOpen
        activeTurnID 在这里被赋值
        audioPending 在这里堆积
        turnStarted 在这里打点
    end note
```

**turn 相关的字段散在三处**：`sessionRuntime`（`rescueTurnID`）、
provider session（`activeTurnID` / `turnStarted` / `audioPending` / `nextAudioSeq`）、
`voiceduplex.DuplexSession`（另一个 `activeTurnID`；当时叫 `voicepoc.DuplexSession`）。

## 五、B8 卡壳救援的状态机

```mermaid
stateDiagram-v2
    [*] --> WindowClosed
    WindowClosed --> WindowOpen: AI 那轮正常结束<br/>（ai.tts.end 或 ai.turn.end）<br/>timeout/error 不开窗
    WindowOpen --> WindowClosed: 用户开口<br/>（user.speech.start）
    WindowOpen --> Rung1: 沉默 3s
    Rung1 --> Rung2: 沉默 6s
    Rung2 --> Rung3: 沉默 9s
    Rung3 --> Exhausted: 三级用尽
    Rung1 --> WindowClosed: 用户开口
    Rung2 --> WindowClosed: 用户开口
    Rung3 --> WindowClosed: 用户开口

    note right of Rung1
        每一级：生成文本 → 发 ai.rescue.ladder
        → 合成 → 按说话速度逐帧发 ai.tts.*
        用户开口 → 发 ai.tts.end(interrupted)
    end note
```

轮询器每 500ms tick 一次；`rescueInFlight` 保证同一时刻只有一级在生成
（它是 busy 标志不是锁——只有轮询器这一个 writer）。

## 六、帧清单与方向

| 帧 | 方向 | 谁产生 | 备注 |
|---|---|---|---|
| `auth` / `session.ready` | C→S / S→C | gateway | 握手 |
| `session.start` | C→S | iOS | 含 scene/material/续接上下文 |
| `user.speech.start/end` | C→S | iOS | end 可带 ASR 文本 |
| `client.turn.abort` | C→S | iOS | 按住不松手；**不回 error 帧** |
| `interrupt` | C→S | iOS | 打断 AI 说话 |
| `ai.text.delta` | S→C | provider | 真增量 |
| `ai.tts.start` / `ai.tts.audio` / `ai.tts.end` | S→C | provider **和** 救援 | 二进制音频的容器 |
| `ai.turn.end` | S→C | provider | 带 outcome（ok/timeout/error/partial） |
| `ai.rescue.ladder` | S→C | 救援 | **只带文本**，音频走 `ai.tts.*` |
| `feedback.badge` | S→C | BadgeEmitter | B7 命中 |
| `error` | S→C | gateway | 非法 JSON / 已知类型的语义错误 |
| `ping` / `pong` | 双向 | 双方 | 保活 |

**未知 `type` 不发 error**，忽略并计数（`unknownFrameCount`）——为的是将来加帧类型不会打死旧网关。

## 七、这张图暴露的三个结构问题

与 `94_` 的发现对应，图本身就看得出来：

1. **两条音频路在 gateway 汇合，但没有共同的表示**：provider 发的是
   `encodeAudioFrame()` 拼的字节，救援发的是 `voiceproto.AITTSAudio.Encode()` 拼的字节
   ——线格式相同，实现两个（`94_` F4）。
2. **`ai.tts.*` 有两个生产者**（provider 与救援），但没有一个"音频流"抽象描述
   "谁在说、说到第几帧、什么时候结束"。序号、切帧、结束帧三件事各写一遍。
3. **turn 的状态在两张图里都有**（会话图的 Collecting、turn 图的 TurnOpen），
   而它们由**不同包的不同字段**表达，没有一处能同时看到两者。
