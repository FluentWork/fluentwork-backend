# 费用与服务端日志现状分析及更新说明

## 一、结论

当前 backend **没有真正实现 token/费用管理闭环**。

已经存在的是：

1. `session_tickets`：WSS 一次性票据
2. `auth_tokens`：登录/游客身份的 refresh token
3. `ai_cost_logs`：成本表结构 migration

真正**还不存在**的是：

1. AI 调用后的同步落账实现
2. token in / token out / 音频秒数 / 成本分的统一写入服务
3. 按 task / user / model 的汇总查询与统计

所以，之前你记得的“ticket 已经做了一部分费用记录功能”这件事，当前代码证据显示是**记忆混淆**：

- `ticket` 相关实现是语音网关票据，不是费用票据
- 费用相关目前只有 `ai_cost_logs` 表和文档纪律，没有业务写入路径

## 二、现状分析

### 1. 已有费用相关资产

数据库 migration 已经存在：

- `migrations/0002_create_ai_cost_logs.sql`

表字段：

- `task_type`
- `model`
- `tokens_in`
- `tokens_out`
- `audio_sec`
- `cost_fen`
- `created_at`

说明仓内已经有**账本结构预留**，但只是“地基”，不是“房子”。

### 2. 已有文档纪律

`docs/02_第二波开发范围与任务清单.md` 已明确写明：

1. 每次 AI 调用必须同步落 `ai_cost_logs`
2. 不允许后补

说明产品/后端设计已经把成本埋点当成强约束。

### 3. 当前缺失点

当前代码库中没有发现：

1. `ai_cost_logs` 的 Store / Repository
2. `ai_cost_logs` 的写入 Service
3. 任何真实 AI 调用后自动写账本的逻辑
4. 任何 token/audio usage 到 `cost_fen` 的换算器

因此，当前只能说：

- **表准备好了**
- **纪律写清楚了**
- **实现还没落**

## 三、服务端日志现状问题

旧状态下的问题：

1. 各进程都直接手写 `slog.New(...)`
2. 没有统一的 logger 工厂
3. 没有统一的“分段日志”写法
4. request logger 只有 request id，没有稳定的组件分层
5. voice-gateway / worker / B14 live smoke 的关键链路缺少阶段化统计字段

这会导致两个后果：

1. 出问题时只能靠零散日志拼现场
2. 后续接真实 ASR / TTS / 编排模块时，很难做稳定统计

## 四、本次更新

### 1. 新增统一日志组件

新增：

- `pkg/logx/logx.go`

提供两类能力：

1. `logx.New(service)`：统一创建 JSON logger
2. `logx.Begin(...).End(...)`：统一分段日志，自动记录：
   - `duration_ms`
   - `outcome`
   - 自定义 attrs

### 2. 启动入口统一接入

已接入：

- `cmd/app-server/main.go`
- `cmd/voice-gateway/main.go`
- `cmd/worker/main.go`
- `cmd/smoke-review-ready/main.go`
- `cmd/smoke-volc-realtime/main.go`
- `cmd/poc-injection-window/main.go`

这样每个进程日志都会稳定带：

- `service`
- `repository`

### 3. HTTP 请求日志补强

已更新：

- `internal/httpserver/middleware.go`

行为变化：

1. `RequestID()` 现在会把 `request_id` 注入 request-scoped logger
2. `AccessLog()` 优先使用 request-scoped logger

这样后续接口层日志和 access log 可以共享同一个 `request_id` 维度。

### 4. 服务端编排日志补强

已更新：

- `internal/session/review.go`

新增分段日志：

1. `session.job.process`

### 6. B14 live ASR/TTS 日志补强

## 五、现在可以回答的问题

### Q1. 当前是否已经涉及 token 费用管理？

答案：**没有形成实现闭环。**

只有：

- 表结构
- 文档纪律

没有：

- 同步落账
- 成本汇总
- 计费换算

### Q2. 之前 ticket 是否已经实现费用记录的一部分？

答案：**没有。**

当前 `ticket` 指的是 `session_tickets`，它服务于：

- voice-gateway 鉴权
- 一次性 WSS 握手

不是费用账本。

### Q3. 服务端日志组件规范是否之前已经实现？

答案：**之前只有基础 `slog` 使用，没有形成统一规范实现。**

本次已经补上第一版统一规范入口和分段日志能力。

## 七、下一步缺口

日志规范这次已经补了第一版，但费用管理仍缺正式实现。后续建议新增：

1. `internal/aicost` 模块
2. `CostLog` store + mysql/memory 实现
3. `RecordLLMUsage / RecordAudioUsage`
4. 统一 cost 计算器
5. worker / review / B7 hit detect / daily read 的同步落账接入

## 八、当前判断

本次更新完成后，backend 的状态是：

1. **费用管理：仍未实现，只完成结构预留与纪律确认**
2. **服务端日志：已从“散点 slog”升级到“统一 logger + 分段日志 + 关键链路统计字段”**
3. **B14 live 链路：已具备更可追踪的 ASR/TTS/注入阶段日志**
