## 一、PRD 核心功能与护城河分析

### 1.1 产品定位（PRD §2-3）

**一句话**: 把你的工作日常变成英语练习——以真实工作场景为料、以口语演练为核心的个性化职场英语训练引擎。

**北极星指标**: 周完成"说 → 回顾 → 入库"完整流水线至少 1 次的用户占比（含迷你会话）

**护城河核心** (PRD §14.3)：
1. **机制**: 间隔重复 + 主动召回（⭐⭐⭐⭐⭐）
2. **沉淀**: 话术块三元组个人资产库（⭐⭐⭐⭐⭐）
3. **内容源**: 用户素材驱动（⭐⭐⭐⭐）
4. **反馈层级**: 结构化镜像（⭐⭐⭐⭐）
5. **实战出口**: 话题建议 → 真人聊天 → 打卡反馈（⭐⭐⭐⭐⭐）

### 1.2 核心闭环（PRD §5.1）

```
说（实战演练）→ 读（自我输出镜像）→ 炼化（话术块萃取）→ 
提取训练（内化）→ 语料库（资产沉淀）→ 话题建议（走向真人实战）
```

#### **P0-2: 回顾生成失败无可观测性** 🔴

**问题描述**（docs/77 P0-15 B）:
- 6 次真实生成失败，错误为 `decode generated json: unexpected end of JSON input`
- **模型原始响应未落日志** - 现在只记 `err`，无法调试
- 这是 P0-9 "读侧真空" 同一形状：**出错的地方没有人在看**

**修法**:
- 在生成器失败路径补完整响应日志（status code + headers + body）
- 区分"空会话"（10 次，正确拒绝）与"JSON 截断"（6 次，真故障）

**验收标准**:
1. 失败时日志包含模型原始响应全文
2. 可区分失败类型（空会话 / JSON 截断 / Schema 违约 / 超时）
3. 失败响应可复现用于调试

**工期估算**: 0.5 dev-day
**前置条件**: 无
**票号**: 81_

> ✅ **已完成**（核对于 2026-09-18）。`reviewgen.GenerateError` 带 `Kind`/`RawContent`/`FinishReason`，

### P1 级 - 结构与质量（不阻塞发布，但影响护城河质量）

#### **P1-1: 卡壳救援 → 炼化的接口未打通** 🟡

**问题描述**（PRD §5.4.4, docs/77 P0-15）:
- 炼化输入除转录外还需**本场救援事件序列**
- 当前炼化只吃转录 → **沉默路径的卡壳点全部丢失**
- 这是 PRD V1.7 §5.5 机制口径登记的第 5 条差异

**修法**:
- D1 接第二路输入：`StuckEvent[]`（卡壳层数 + 场景意图 + 用户是否开口）
- 按 §5.2.2 两条路径分别处理锚点来源

**验收标准**:
1. 沉默 → 救援 → 开口，该轮产出的话术块锚点 = 用户实际说的第一句
2. 沉默 → 救援 → 始终未开口，记录卡壳事件但不产话术块
3. 未完成句 → 救援，锚点 = 用户那半句原文

**工期估算**: 1 dev-day
**前置条件**: P0-1 完成后
**相关**: PRD §5.4.4

> ✅ **已完成**（核对于 2026-09-18）。`reviewgen.Request.StuckEvents` 是炼化的第二路输入；
> 网关按 §5.2.2 解析锚点（未完成句 = 那半句原文，沉默后开口 = 第一句，始终未开口 = 空锚点即不产块），
> 随 `session.end` 上报。测试：`internal/voicegateway/rescue_log_test.go`（三条锚点规则）、
