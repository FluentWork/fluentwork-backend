# 语音链路成本记账

**日期**：2026-09-11
**状态**：实现与测试已齐。门禁见 §6。
**对应**：meta `77_` **P0-3**（语音链路零成本记账）· 执行计划**步 4**

## 1. 守住的不变量

**先把用量记成事实，再把用量算成钱。** 这两件事的确定性差得很远，混在一起做，低确定性的那一半会污染高确定性的那一半。

## 2. 缺口

`ai_cost_logs` 里语音链路**一行都没有** —— 而 duplex 大概率是可变成本的主体。后果是三件事同时做不到：**无法定价、无法熔断、无法归因**。

账本本身早就有 `AudioSec` 列（此前只有 review 在用 token 那两列）。

## 3. 关键判断：两个方向的音频秒数是直接可测的

**不需要供应商的 usage 事件** —— duplex 协议根本不报 token 数。而网关手里有：

| 方向 | 来源 |
|---|---|
| 上行 | `HandleClientAudio` 的每一块 PCM |
| 下行 | `TurnResult.AudioPCM` |

两个方向的字节数都是确定的，速率由线格式固定：16 kHz mono s16le（上行，32 B/ms）、24 kHz mono s16le（下行，48 B/ms）。

## 4. 方案：三层，逐层可测

```
provider 测量        voiceUsage（纯类型）
    ↓ VoiceUsageReporter
网关 → app-server    POST /internal/v1/sessions/end 的 voice_usage 字段
    ↓
app-server          buildVoiceCostLog → 一条 voice.duplex 行，同一事务写入
```

### 4.1 测量层：抽成纯类型

`voiceUsage` 与 `AudioFrameDropPolicy`、`AudioDropReport` 同一个理由：**算术是唯一会静默出错的部分**，要能脱离 socket 测。

两处累加点都放在**守卫之后**：

- 上行在格式/空帧检查之后 —— 被丢弃的帧不算"音频到达了供应商"
- 下行取 `turn.AudioPCM` 的原始长度（24k，**重采样之前**）—— 那才是供应商产出并计费的音频

### 4.2 传输层：`omitempty` 是承重的

`voice_usage` 在 `EndSessionRequest` 里是 `*VoiceUsage`，线上是 `omitempty`。

**发一个零值对象会被读成"测到了，但这段音频没动"** —— 那是一条假记录。nil 与零值是两回事，一路保到账本层。

### 4.3 账本层：`CostFen` 恒为 0

**这是本票最重要的决定。**

供应商的计费单位**未核实**：其官方文档在输出-文本费率上自相矛盾，一处按 80、一处按 30，**相差 2.67 倍**（meta `77_` P2-2，结论是"以账单为准"）。

> 账本里一个按**猜测**费率算出的数字**看起来权威**。它会被拿去定价、拿去熔断，而且**没人会重新推导它**。

所以第一版只记：`task_type = voice.duplex`、`model`、`audio_sec`，`cost_fen = 0`。**用量是事实，费率是待核实。** 归因和熔断靠 `audio_sec` 就能做；定价等账单。

**为什么 `Model` 要跟着用量一起传**：账本的归因离了它没意义，而网关是唯一知道它的地方（P2-1：我们配置的版本和文档写的版本本来就对不上）。

### 4.4 事务与幂等

`EndSession` 把**会话结束、转录替换、账本行**放在**同一个事务**里 —— 不能出现"用量计了费但转录丢了"或反之。这与 `MarkSessionReviewedWithCost` 同一条纪律：**`costTx` 未接线就拒绝执行**，而不是写一半。

重放的 `end` 走 `alreadyEnded` 早退，不会重复计费。

## 5. 已知局限（记录在案，不隐藏）

`ai_cost_logs` 只有**一列** `audio_sec`，所以网关发来的上下行拆分在写入时被**求和后丢失**。

在还没有定价之前这没关系。**如果将来两个方向定价不同，这是第一个要改的地方 —— 那时需要的是加列，不是换个求法。**

## 6. 门禁

```bash
./scripts/dev-check.sh
# All checks passed.
```

**本票是能力新增，红/绿不适用**（`agents/shared/defect-fix-discipline.md` 例外一）：账户里原来没有语音行，不是"有个失败的行为"要复现，所以没有"修复前的失败输出"可贴。测试锁定的是期望行为：

| 测试 | 守住的 |
|---|---|
| `TestVoiceUsageMeasuresEachDirectionAtItsOwnRate` | 两个方向各自按自己的速率换算 |
| `TestVoiceUsageDoesNotShareOneRateAcrossDirections` | **两个方向速率不同（16k vs 24k）—— 共用一个速率，数值依然"合理"** |
| `TestVoiceUsageFloorsPartialMilliseconds` | 取整向下 —— 部分毫秒不是音频 |
| `TestVoiceUsageIgnoresNonPositiveChunks` | 被丢弃的帧不计费 |
| `TestEndSessionCarriesVoiceUsageWhenMeasured` | 用量活到线格式上 |
| `TestEndSessionOmitsVoiceUsageWhenUnmeasured` | **`omitempty` 是承重的**：报不了用量时一个字段都不发 |
| `TestSnapshotVoiceUsageIsNilWithoutAReporter` | 不实现 reporter 的 provider 一律 nil |
| `TestBuildVoiceCostLogRecordsSecondsAndLeavesMoneyAtZero` | 记秒数、`CostFen` 为 0、用户可归因 |
| `TestBuildVoiceCostLogIsNilWithoutUsage` | nil 用量不写行（不是写零值行） |
| `TestBuildVoiceCostLogClampsNegativeMilliseconds` | 负毫秒不许抵扣总数 |
| `TestBuildVoiceCostLogFloorsPartialSeconds` | 不足一秒不算一秒 |

线格式的测试**直接看发出去的 JSON**，不断言 `EndSessionRequest` —— 断言进程内类型证明不了发出去的是什么。

## 7. 本票不做

- **不算钱**：见 §4.3。费率核实后回填，不是现在猜一个。
- **不加列**：见 §5。拆分目前在网关侧可见、未持久化。
- **不覆盖 review 那条路**：它已经在记 token 账，本票只补语音这条。
