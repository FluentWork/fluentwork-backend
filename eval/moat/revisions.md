# 机制修订记录

**为什么有这张表**：`86_ M12` 的纪律——**每次修订必须记录前后指标**。没有前后对比的"优化"
无法证明飞轮在转，只会积累不可验证的改动。每一条都回答两个问题：**改了什么**、
**哪个数字因此变了**。

格式（新条目加在最上面）：

```
## YYYY-MM-DD — <一句话说清改了什么>
- 依据：<哪个信号说明需要改>（卡壳视图 / 负反馈率 / 判定准确率 / 实战转化率）
- 改动：<文件或机制>
- 前后：<指标> A → B（测量方式）
- 结论：<保留 / 回滚 / 继续观察>
```

## 2026-09-18 — B8 卡壳救援从未接线：接上，但只在"能真正送达"的环境默认开启

- **依据**：按 F1 的教训体检救援链路时发现——`SetRescueComponents` / `NewSilenceDetector` /
  `NewRescueOrchestrator` **只在测试里出现过**，`cmd/voice-gateway/main.go` 一字未提。
  也就是说：沉默检测、三层梯子、救援事件（炼化的第二路输入）、卡壳地图的救援分列，
  在**所有部署里都是关闭的**（handler 注释自己写着"nil detector 就是这个功能的开关"）。
  规划文档记的"B8 已完成、真机验证通过"指的是 AEC 那一半，机制本身从未上线。
- **改动**：网关接线（无 LLM 时走固定梯子库，这是代码里既有的降级路径）；
  新增 `VOICE_RESCUE_ENABLED`，**默认跟随环境**：development 开、production 关。
- **为什么不在生产默认开**：iOS 侧没有任何 rescue 处理，TTS 也未授权（P1-3/P2-4）——
  梯子发出去用户看不到也听不到。那样只会让数据**谎称救援发生过**（卡壳地图的救援列
  会填满，而用户什么都没经历），正是这次审计一路在消除的自欺。
- **前后**（救援事件数据）：
  | 项 | 前 | 后 |
  |---|---|---|
  | 网关接线 | 无（机制关闭） | dev 默认开、生产一行环境变量可开 |
  | 救援事件（炼化输入） | 永远为 0 | dev 有真实数据 |
  | 卡壳地图 rescues 分列 | 永远为空 | dev 可读 |
  | 用户可感知的救援 | 无 | **仍为无**（等 iOS + TTS） |
- **结论**：保留。生产开启的前提是"梯子能送达"：iOS 渲染 + TTS 授权（P1-3 → P2-4）。

## 2026-09-18 — 空会话不再进回顾管线（P0-3 方案 A）

- **依据**：产品决策 P0-3。每次「重新开始」都建一场空会话，它进回顾管线后被生成器
  正确拒绝（`failure_kind=empty_session`），但已经产生了一条 stub 回顾、一个
  `session.finished` 作业和一次 B18 评估入队——每次误触都留下垃圾行与账本记录。
- **改动**：`session.End` 按"有没有用户发言"判定空会话 → 不入队、不产 stub；
  回顾轮询新增终态 `empty`（此前返回 `pending`，客户端会一直轮询一个永不存在的回顾）。
- **前后**（单场空会话）：
  | 项 | 前 | 后 |
  |---|---|---|
  | session.finished 作业 | 1 | **0** |
  | B18 评估入队 | 1 | **0** |
  | stub 回顾记录 | 1 | **0** |
  | 回顾轮询终态 | pending（永不结束） | **empty** |
- **结论**：保留。客户端半边（首次开口才建会话）待 iOS 排期。

## 2026-09-18 — 端点路由：六个端点此前只有一个被调用

- **依据**：记账核对时发现 `drill.judge` 的 `model` 列写着 pro，而 DRILL_JUDGE 端点背后是 turbo。
- **改动**：`orchestrator` 按 operation 路由；判定/话题改走各自端点；未配置路由回落 review。
- **前后**：无质量指标变化（同 prompt、同一批样本）；判定与话题的**成本与延迟下降**
  （turbo 端点），账本 `model` 列开始如实反映每个任务实际用的模型。
- **结论**：保留。

## 2026-09-18 — 话题卡：H2 从标签层升级到正文层 + 跨天去重

- **依据**：裁判在能看到用户语料后，5/9 张卡判为泛话题，三种形态——standup 模板化、
  面试题脱离语料、跨天重复。
- **改动**：`topic.groundCard` 改为正文匹配（须逐字引用用户语料 ≥4 个连续词，否则丢弃）；
  prompt 明写该规则；跨天重复在 prompt 与服务端双重拦截。
- **前后**：跨天重复被丢弃（一轮实测 9 张 → 6 张）；卡片全部携带可核对的块清单。
  **质量指标本身尚不稳定**（四种测量设计给出 0.556/0.444/0.000/0.333），因此暂不门禁，
  以人工抽检为准。
- **结论**：结构约束保留；**质量结论待人工抽检**。

## 2026-09-18 — 闪测判定：超时不再算答错 + rubric 写死"要点覆盖即通过"

- **依据**：Flow Eval 100 条实测（首发）——判定准确率 0.792、生产预算超时率 0.969，
  且 40/200 个判错**全部**是"说了要点但没逐项说全被判失败"，与 PRD §7.5 冲突。
- **改动**：`drill.JudgePrompt`（rubric 改写）；`LLMJudge`/`JudgeResponse` 增 `Judged`/`Retryable`；
  未判定尝试不再动调度（migration 0023）；预算 1.5s → 6s。
- **前后**（同一批 100 条 mock，金标集不变）：
  | 指标 | 前 | 后 |
  |---|---|---|
  | 判定准确率 | 0.792 | **0.974** |
  | 生产预算超时率 | 0.969 | **0.005** |
  | 炼化地道度均分 | 4.63 | 4.83 |
  | 评价真实性均分 | 3.84 | 4.18 |
- **结论**：保留。副作用：判定变严/变松的边界需人工抽检复核（见 `docs/87` §七 L3）。
