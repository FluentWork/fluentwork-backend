## 二、核心能力

### 2.1 统一接口

```go
type Client interface {
    Complete(ctx context.Context, req CompletionRequest) (CompletionResponse, error)
}
```

**优势**:
- 业务层不依赖具体供应商
- 测试时可替换为 MockClient
- 后续支持多供应商切换

### 2.2 自动成本记账

每次 LLM 调用自动写入 `ai_cost_logs`，无需业务层手动处理：

```go
client := orchestrator.NewClient(cfg, costWriter)
resp, err := client.Complete(ctx, CompletionRequest{
    Operation: "review.eval", // 自动记账标识
    // ...
})
// ai_cost_logs 已自动写入
```

### 2.3 测试友好

```go
// 测试中无需真实 LLM
client := orchestrator.NewMockClient(`{"score": 85}`)
resp, err := client.Complete(ctx, req)
// 立即返回预设响应，不产生费用
```

## 四、与临时缝的对比

| 特性 | drill.ArkCompleter | orchestrator.Client |
|---|---|---|
| **成本记账** | ❌ 手动 | ✅ 自动 |
| **System Prompt** | ❌ 不支持 | ✅ 支持 |
| **测试** | ⚠️ 需 httptest | ✅ MockClient |
| **接口抽象** | ❌ 具体类 | ✅ Interface |
| **思考链控制** | ❌ 未关闭 | ✅ 自动关闭 |
| **Operation 标记** | ❌ 不支持 | ✅ 支持 |
| **统一响应** | ⚠️ 只有 content | ✅ tokens+latency |

## 五、迁移路径

### 5.1 B18 迁移示例

**Before** (drill.ArkCompleter):
```go
completer := drill.NewArkCompleter(cfg)
result, err := completer.Complete(ctx, prompt)

// 手动记账
costService.LogCompletion(ctx, aicost.CompletionLog{
    Operation: "review.eval",
    // 需要手动填充 tokens...
})
```

**After** (orchestrator.Client):
```go
client := orchestrator.NewClient(cfg, costWriter)
resp, err := client.Complete(ctx, orchestrator.CompletionRequest{
    Prompt:      prompt,
    MaxTokens:   2000,
    Temperature: 0.7,
    Operation:   "review.eval", // 自动记账
})
result := resp.Content
// 成本已自动记录，包含准确的 token 数
```
